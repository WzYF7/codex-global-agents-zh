# Codex 全局工作约定

一份面向中文用户的 `AGENTS.md` 模板，适合用 Codex 查资料、做 PPT 和 HTML、学习带练，以及处理日常文件和代码任务。

我有一次带着已经写好的大纲请 Codex 做课堂 PPT，拿到成品后还是不满意。回头看，我们讨论过讲什么，却没确认我要的是一份自己还能继续改的初稿，还是一份打开就能上台讲的演示稿。类似的事情遇到几次之后，我把希望 Codex 下次能提前判断的问题写进了这份规则。

## 这份规则怎么工作

| 场景 | Codex 应该怎么做 |
| --- | --- |
| 改一处文字、核对一份文件 | 按已经明确的要求直接做，验证关键结果。 |
| 做 PPT、网页或交互式复习资料 | 沿用已有大纲。如果受众、用途或完成程度会改变成品，先问最关键的一点。需要时先用一页样稿或一个关键交互确认方向。 |
| 查论文、软件资料或使用体验 | 按问题选来源。论文查学科数据库和原文，软件查官方文档、源码和发布记录，教程或实际体验再按需查视频和社区。 |
| 需要带练或备考 | 按基础讲解，出题后等你作答，再根据错因给提示、解析和变式练习。需要整套复习资料时，可以做成离线 HTML。 |
| 遇到影响较大的取舍 | 先说明做法、代价和自己的建议。可能改变成品方向、造成大量返工或明显增加用量时，先一起决定。 |

简单任务用最短的可靠路径。复杂任务也尽量复用已经查到的材料，把额外的工具调用和检查用在会影响结论或交付的地方。交付时按实际用途试用关键功能，例如打开复习网页答一道题，确认提交后会给出反馈。

## 快速开始

1. 打开[模板文件 AGENTS.md](./AGENTS.md)，先把背景、偏好的协作方式和资料存放规则改成你的实际情况。
2. 想让规则跨项目生效，就合并到 Codex 主目录下的 `AGENTS.md`。默认位置是 `~/.codex/AGENTS.md`，Windows 通常可以从文件资源管理器打开 `%USERPROFILE%\.codex`。设过 `CODEX_HOME` 就用对应目录。已有全局文件时先备份，再合并你需要的段落。
3. 只想在一个项目里试用，就把选中的规则放进项目根目录的 `AGENTS.md`。启动新的 Codex 会话，问一句“制作 PPT 时你会先判断什么？”，看看回答能否复述你刚写进去的约定。

同一目录有非空的 `AGENTS.override.md` 时，Codex 优先读取它。项目规则可以补充通用约定，例如汇报材料放在哪、代码怎么测试。[Codex 官方配置指南](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 用你自己的任务来改

可以先拿这两个请求试试：

> 按这个大纲做一份给同学看的 PPT，下周我要在课堂上讲 8 分钟。

> 把这三页笔记做成一份离线 HTML。我要能答题，提交后看到解析。

试过几次之后，挑最让你省事或最容易返工的一步来改规则。比如，你发现自己每次都要补一句“给我能直接上台讲的版本”，就可以把适用场景和完成标准写进约定。Codex 也可以顺带提出它观察到的改进项，准备长期保存时先查同义规则，再由你确认是否写入。

模板里的学习、检索和制图技能按实际任务和环境选用。这份 Markdown 可以独立使用。对于某个项目才有意义的模板、目录和操作习惯，写到对应项目的规则里更方便维护。
